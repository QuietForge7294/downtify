# Weekly DJ assets and saved copies

Weekly audio sets now have an owner-scoped metadata index at `GET /api/v1/music-ai/dj/weekly`: ten themes including Rock, Rap, Pop and Electro, four featured sets rotated daily with ready audio first, progress/duration/track counts, and up to twenty saved copies. The request checks current native ACLs without reading or enumerating NAS music. It never schedules analysis, rendering or downloads.

`POST /dj/weekly/{theme}` explicitly prepares a current weekly selection, up to 25 distinct accessible native tracks and a 20 minute source limit. It uses the same low-priority single background queue as automatic catch-up. New workers advertise `weekly_protocol=1`; old heartbeats cannot receive scheduled weekly work. Automatic request receipts prevent eviction/deletion from triggering a regeneration loop. No preference is enabled implicitly: `weekly`, `dj_prepared` and `dj_weekly` must all be enabled globally and for the owner.

`POST /dj/sessions/{id}/copies` accepts `request_id` and a name. It preserves the exact accepted audio and chapter metadata using a private immutable hard link, verifies SHA-256, and publishes atomically. Source deletion does not delete the copy. A retry after audio publication but before the database commit can finish even if the source expired. A repeated identifier must retain its original intent. Twenty accepted/in-flight copies per owner are allowed. Copies remain permission/ACL scoped; originals, native queues and native playlists are unchanged.

The private DJ cache has a maximum budget of 5 GiB and a 2 GiB free-storage reserve. Render I/O and copies request space under the shared compute lease. Inactive sets are reclaimed by last access; active render work, reader-pinned audio and accepted saved copies are excluded. Hard links are counted conservatively twice. Prepared transport stop releases that reader's pin while retaining replayable audio. Explicit discard rejects a still-pinned set. Per-device legacy readers remain compatible; new browser tabs can send separate consumer IDs. Pins have bounded expiry and playback status renews them even on HTTP 304. No background download or radio is created.

Validation: the targeted API, assets, scheduler, real FFmpeg I/O and real pinned BeatThis model tests passed (77 tests). Tests cover ownership, idempotency, source expiry, interrupted publication, multiple readers, default-off behavior, legacy worker rejection and replay after stop. Full suite: 3,654 passed, zero skipped, ten subtests passed in 166.17 seconds. Monitored single-core run: 167.202 seconds wall time, maximum aggregate RSS 654,602,240 bytes, no resource-budget violation. An earlier restricted-environment run was interrupted while stuck at the start and is not counted as validation. These tests use synthetic audio; they do not qualify real-library diversity, sound quality, sustained throughput, phone battery or Android Auto hardware behavior.

Not deployed. Requires a coherent API/worker deployment and compatible client. The existing native download/improvement queues must be paused through their native control and allowed to finish their current track before any authorized service replacement. Cache orphan cleanup and real catalog/vehicle qualification remain separate pending work.
